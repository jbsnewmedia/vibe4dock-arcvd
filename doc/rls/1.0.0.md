# Release 1.0.0 – Initial Release

This release introduces the first stable version of **vibe4dock-arcvd**: a single-container, all-in-one Docker image that serves a start page, an AI chat, the Veronica assistant, a git diff UI, and browser shells through one HTTP(S) port with path-based routing.

*Name*: **arcvd** = **A**pplication · **R**oot · **C**hat · **V**eronica · **D**iff.

* **Single-Container All-in-One Architecture**
  Ships the Vibe4Dock start page, the Chat UI, Veronica, the Vibe-Diff git UI, and two browser shells in one image based on `webdevops/php-apache:8.5` (Apache + PHP-FPM). The opencode backends and ttyd shells run supervised (supervisord, auto-restart, stale PID handling).
  *Benefit: a complete environment with a single `docker run` or `docker compose up` - no multi-container stack required.*

* **Path-Based Routing with Configurable Prefix**
  All services live under configurable `/{VIBE_PREFIX}-*` routes (default `vibe`): `/vibe-chat`, `/vibe-veronica`, `/vibe-diff`, `/vibe-shell-root`, `/vibe-shell-app`.
  *Benefit: run the image behind existing hosts or side by side with other projects without port conflicts.*

* **Environment-Driven Ports and Branding**
  `HTTP_PORT` and an optional `HTTPS_PORT` (self-signed certificate auto-generated or mounted via `SSL_CERT_PATH`/`SSL_KEY_PATH`) are set at runtime. `VIBE_NAME` drives the PWA app name and the start page title (`$VIBE_NAME - Vibe4Dock`), `SHELL_HINT` the persistent tmux status bar inside the shells.
  *Benefit: one image fits local, staging, and TLS-terminated production setups without rebuilds.*

* **Per-Service HTTP Basic Auth via Environment**
  Start page, chat, Veronica, and both shells can each be protected with `*_USERNAME` / `*_PASSWORD` pairs; protection activates only when both values are set.
  *Benefit: selective, reproducible access control entirely through the compose environment.*

* **Server-Side Veronica User Database (JSON)**
  User accounts are stored in a JSON file below `/data` (outside all web roots), managed through an authenticated GET/PUT API with atomic writes (flock + tmp/rename). The UI syncs on load and writes registrations and admin changes back; `localStorage` remains an offline cache. Optional bootstrap seeding of the admin account via environment variables with the UI-salted PIN hash scheme (`veronica:<alias>:<pin>`).
  *Benefit: users survive browser changes, container rebuilds, and restarts - without an external database service.*

* **Plan Mode Toggle (Veronica)**
  A header toggle sends a kickoff prompt with opencode's `plan` agent (`agent: 'plan'`) directly into the session. While on, every message from the send button runs in plan mode; the state persists across reloads.
  *Benefit: one click switches Veronica from building to planning, with the full opencode plan-agent interaction (questions, options) through the chat UI.*

* **Vibe-Diff: Git Working Tree UI**
  Browser UI for the repo behind the code: current branch, branch list (with checkout), last 50 commits, changed files, unified diff view with **line-level and block-level revert** (like an IDE) plus whole-file revert. Repo path via `VIBE_DIFF_REPO` (default: parent of the webroot, i.e. `git ../` relative to the webroot); paths are validated to stay inside the repo.
  *Benefit: review and roll back working tree changes from the browser without an IDE.*

* **Integrated opencode Backends with Flexible Configuration**
  Chat and Veronica each run their own `opencode serve` instance, configured through shared `OPENCODE_*` variables with optional per-service overrides (`CHAT_OPENCODE_*`, `VERONICA_OPENCODE_*`).
  *Benefit: independent model and provider configuration per assistant in one container.*

* **DE/EN UI with Browser-Language Default**
  Chat and Veronica ship a DE/EN switch (persisted in `localStorage`, shared across apps); the language follows the browser setting by default. All dynamic views re-render on switch, including open agent questions.

* **PWAs for Chat and Veronica**
  Installable web apps (manifests, icon set with maskable variant, service worker). App name follows `VIBE_NAME`; favicon legible at 16 px on dark and light tab bars.

* **Security Hardening**
  Security headers on every response (X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy deny list, baseline CSP), `ServerTokens Prod`/`ServerSignature Off`. The Veronica user database lives below `/data` - outside all web roots and never served.

* **Release Automation**
  A GitHub Actions workflow builds and pushes two image variants to Docker Hub - production (`jbsnewmedia/vibe4dock-arcvd`) and a dev variant with xdebug/composer tooling (same repository, `-dev` tag suffix) - on every `main` push (`latest`) and on semver tags (`1.0.0` -> `1.0.0`, `1.0`, `latest` + `-dev` variants; bare and v-prefixed tags both supported).
  *Benefit: reproducible releases with immutable patch tags and a re-publishable minor tag.*

**Compatibility:** Docker with Compose v2; designed for `linux/amd64` hosts. Credentials, model settings, ports, and branding are configured exclusively through environment variables (see `.env.example`).

**Known Differences from the Multi-Container Stack:** no tools dashboard or addon management, and browser shells use HTTP basic auth instead of the form login.
