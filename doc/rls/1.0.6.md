# Release 1.0.6 – Actionable Provider Errors & Stale Model Recovery

Patch release after 1.0.5. Everything below is backwards compatible.

* **Free-Tier 403 Explains Itself (Veronica + Chat)**
  OpenCode's free-tier models (`opencode/big-pickle` and friends) reject every request that does not come from the OpenCode client itself: `403 "OpenCode's free tier can only be used from within OpenCode"`. When no provider is configured, the server silently falls back to exactly such a model - the chat then died with a cryptic provider error (or nothing at all). Both UIs now detect the `FreeTierError` pattern and render an actionable hint instead: pick another model in the model menu, or have the operator configure a real provider (`OPENCODE_PROVIDER`/`OPENCODE_MODEL` or `opencode auth login`). Available in German and English.
  *Benefit: end customers see what to do next instead of a raw provider message.*

* **Stale Model Selections Heal Themselves (Veronica)**
  A model picked in the Veronica menu is stored in `localStorage` and sent with every prompt. If the provider/model later disappears server-side (moved deployments, wiped `auth.json`, provider key rotated away), the UI kept sending the dead pair - every message failed until the user manually re-picked a model. The menu's model catalog is now the source of truth: a stored selection that is no longer offered is dropped automatically, a notice informs the user, and the server's default model takes over.
  *Benefit: provider config changes no longer brick existing browser sessions.*

* **Assistant Errors Visible In The Chat App Too**
  Release 1.0.5 made failed assistant messages visible in Veronica; the developer-facing Chat app still swallowed them (errored message, empty parts, no bubble). The Chat UI now renders the same red error box - including the free-tier hint above.
  *Benefit: both apps fail loudly instead of silently.*

**Note for operators:** this release pairs well with the provider basics - set `OPENCODE_PROVIDER`/`OPENCODE_MODEL` (plus `OPENCODE_API_KEY`) in the instance `.env`, or run `opencode auth login` once in the application shell. Provider auth and the default model live in the mounted `opencode/` volumes and survive container rebuilds.

**Compatibility:** drop-in for 1.0.5. No new environment variables, no schema changes.
