# Release 1.0.5 – Model Selection & Visible Assistant Errors

Patch release after 1.0.4. Everything below is backwards compatible.

* **Selected Model Is Now Actually Used**
  Veronica and the Chat UI stored the picked model but sent it as flat `providerID`/`modelID` fields on `POST /session/:id/prompt_async` - fields the opencode v2 API ignores. opencode therefore always fell back to its default model (typically the OpenCode Zen free tier, which fails outside the OpenCode client with a 403 `FreeTierError`). The model is now sent the way the API expects: `body.model = { providerID, modelID }` (plan-mode GO and queued prompts included). The `variant` recorded by the opencode TUI (`models.json`, e.g. `max`/`thinking`) is passed along as well.
  *Benefit: picking a model in the chat actually switches to it - same model as the opencode TUI shows.*

* **Assistant Errors Are Visible In The Chat**
  A failed assistant message (API error, empty parts, `error` on the message) rendered as nothing: no bubble, no typing indicator, silent chat. Failed answers now render as a red error box inside the assistant bubble showing the provider error text (e.g. "Error from provider (Console): OpenCode's free tier can only be used from within OpenCode").
  *Benefit: no more black-hole messages - you see immediately why Veronica stayed silent.*

* **Model Menu Names Match The Chat**
  The Veronica model menu synthesized "ghost" entries with raw IDs for favorites the backend did not list (e.g. `glm-5.3-flash (zai-coding-plan)`). The menu now offers only models known to `/config/providers` - exactly like the Chat UI - so entries show their catalog names (`GLM-5.3-Flash (Z.AI Coding Plan)`, `MiniMax-M3 (MiniMax Token Plan (minimax.io))`, ...). The stale-opencode fallback (bare `opencode` provider after a cold start) no longer displays fake entries for models the server cannot resolve.
  *Benefit: the model picker shows the same clean, real names in Veronica as in the Chat app.*

**Note for operators:** the opencode daemon per app loads its provider/auth state at start. If the model menu ever shows only "OpenCode Zen" although `auth.json` has more providers (e.g. after copying state into a running container), restart the opencode process (or the container) so it re-reads the state.

**Compatibility:** drop-in for 1.0.4. No new environment variables, no schema changes - the model choice still lives in the browser's `localStorage` (`vibe4dock.veronica.model` / `vibe4dock.chat.model`).
