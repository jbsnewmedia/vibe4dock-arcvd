# Release 1.0.4 – Persona, Upload-Posts & Project Layout

Patch release after 1.0.3. Everything below is backwards compatible.

* **Veronica Persona**
  Veronica now runs on her own persona: when asked who she is, she answers "I am Veronica from Vibe4Dock, the assistant system by JBS New Media GmbH in Worms." The persona is provided as a hidden opencode agent generated at container start - it does not appear in any agent picker and cannot be selected accidentally.
  *Benefit: Veronica has a stable, consistent identity in every conversation.*

* **Plan Mode Runs Inside the Persona**
  The plan toggle keeps its familiar behaviour (enable to plan, disable to send the GO). Internally Veronica no longer switches to the generic plan agent: in plan mode she runs as `veronica-plan`, the same persona with all file tools (write/edit/patch) disabled at agent level. She keeps her identity and context in both modes and - while planning - cannot create, modify or delete files, no matter what the prompt asks for. She confirms the restriction and hands back a concrete implementation plan; the actual change happens after the toggle-off GO as usual.
  *Benefit: plan mode is enforced by the runtime, not by prompt politeness - and Veronica stays Veronica in both modes.*

* **File Posts Live Below Their Message**
  Uploads no longer appear as a chat post while still composing. A file post appears only after the message mentioning it is actually sent - directly below that message and containing exactly the files referenced in it (one post per message, user and assistant messages alike). Files that are never mentioned in a sent message never appear as a chat post.
  *Benefit: the file post is exactly where the conversation references it - no wandering, no duplicate "all files" bubble at the bottom.*

* **@ Mentions Are Links**
  File mentions (`@name` / `@incoming/name`) in sent messages render as links. Clicking one scrolls to the file post directly below the mentioning message and gives the card a short shake. If no post exists for that file, the file itself opens.
  *Benefit: one tap from any mention to the file it refers to.*

* **No More Refresh Flicker**
  Message rendering is now incremental: new messages are appended, the running (streaming) tail message is replaced in place, and a full rebuild only happens on real structural changes. Verified that DOM nodes survive polling and streaming untouched.
  *Benefit: the chat stays visually stable while the assistant is typing - no blinking images or scroll jumps on every refresh.*

* **Optional Answers No Longer Block Questions**
  In the question flow, pressing Enter with an empty free-text field on a question that offers options now skips that question ("(keine Angabe)") instead of doing nothing. Previously such questions could feel stuck.
  *Benefit: question flows finish even when a question is not relevant to you.*

* **Voice Message Button Disabled**
  The microphone button in the Veronica composer is hidden for now. The complete recording feature remains in the codebase behind a single flag and can be re-enabled later without any rework.

* **Project Layout: Repo at /app, public/ as Web Root**
  The image payload moved from `/app/*` to `/opt/vibe/*`, so the project repo can be mounted at **`/app`** (compose pattern `./:/app`, like any plain PHP project). When the repo contains a `public/` directory it is served as the web root at `/` and the agents work in `/app` - files survive container rebuilds by construction. Without a project (or without `public/`) the Vibe4Dock start page is served, always reachable at **`/{VIBE_PREFIX}-start`** as well. The classic `./project:/app/project` mount keeps working; `VIBE_PROJECT_DIR` overrides the detection.
  *Benefit: one container, one bind mount - project, agent workspace and web root live exactly where a plain PHP project expects them.*

**Compatibility:** drop-in for 1.0.3. Note for the project layout switch: add the `./:/app` volume when recreating the container - existing `./project:/app/project` setups continue to work unchanged. No new required environment variables; optional `VIBE_PROJECT_DIR` / `VIBE_WEB_ROOT`.
