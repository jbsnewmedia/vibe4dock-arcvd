# Release 2.0.0 – OpenCode v2

**Breaking release:** the image moves from OpenCode 1.x to **OpenCode 2.x** (`opencode.ai/v2/install`). OpenCode 2 intentionally changes its server API, so the Chat and Veronica UIs were ported to it. Drop-in is NOT guaranteed for external API consumers; for the bundled UIs behavior is preserved.

* **OpenCode 2 in the image**
  The opencode CLI is now installed from the v2 installer channel. Existing session databases (SQLite) are migrated in place on first start - chat history survives the upgrade (tested against 1.18.x databases).

* **Server API: /api/*, {data} envelopes, Basic auth**
  v2 moves every endpoint under `/api/*`, wraps list responses in `{ data: ... }` with cursor pagination, and protects the server with HTTP Basic auth using a per-start random password. The container handles this transparently: the opencode process wrappers extract the password from the server log and inject it as an `Authorization` header into the Apache proxy via the new `vibe-auth-update` sudo helper (fragment under `/etc/vibe/auth/`, applied with `apache2ctl graceful`).

* **UIs ported to the v2 contracts (Chat + Veronica)**
  - Prompts: `prompt_async` → `POST /api/session/{id}/prompt` with plain `text`; model, variant and agent are now set per session beforehand (`POST /api/session/{id}/model` / `/agent`).
  - Messages: flat typed messages (user `text`, assistant `content[]` with text/reasoning/tool) are normalized back into the UIs' `{info, parts}` shape; new event-ish message types (idle/agent-switched/model-switched) are hidden.
  - Questions: the v1 `/question` endpoint is gone; the UIs now render v2 **forms** (`GET /api/form`, reply `POST /api/session/{id}/form/{id}/reply` with structured `{ answer: { fieldKey: value } }`). Sniffed tool-part questions remain as a fallback and are sent as text prompts.
  - Permissions: `GET /api/permission/request` + reply `{ decision }` (same once/always/reject values).
  - Model menu: built from `GET /api/model` (+ provider names via `GET /api/provider`, default via `GET /api/model/default`). The catalog loads lazily in v2, so the menus retry longer. Variant selection is seeded from the legacy `model.json` and then kept in `localStorage`.
  - Abort: `POST /api/session/{id}/interrupt`.

* **Credentials: auth.json → SQLite**
  v2 stores provider credentials in its database. At container start the entrypoint converts the legacy `auth.json` (read-only mount) and imports it via `opencode auth import` - only while the database has no credentials yet, so restarts are idempotent. New logins should use `opencode auth login` in the application shell.

* **Agents: `agents/` directory, v2 frontmatter**
  Generated agent files now live in `~/.config/opencode/agents/` and use v2 frontmatter (`permissions:` rules instead of the legacy `tools:`/`permission:` maps). Deployments that bind-mount agent files must switch their mount paths from `agent/` to `agents/` (allindocker does this with the same release).

**Operator notes:** pull/rebuild the stack, the DB migration runs automatically. `models.json` favorites keep working as a seed; V2 no longer writes that file. First model-menu fill after a fresh start can take a few seconds (lazy catalog).

**New V2-powered features in this release:**
- **Live updates via SSE** (`/api/event`): Chat and Veronica react to server events within ~250 ms; the 1.5 s poll remains as fallback. ProxyPass uses `flushpackets=on` so the stream survives both Apache hops.
- **Steer while generating:** messages sent during a running generation now steer the run (V2 delivery semantics) instead of being queued client-side or blocked (Chat: Senden stays active, commands still wait; Veronica: API mode steers, mock mode keeps the queue).
- **Cost/token display** per session in both sidebars (from `Session.Info.cost`/`tokens`).
- **Session outcome icons** (✓ succeeded / ✗ failed / ⏸ interrupted) in both sidebars.
- **Chat: session fork** (⎘ per session) via `/session/{id}/fork`, **compact** (→) via `/session/{id}/compact`, and a **session diff viewer** (⎦ Diff in the topbar) listing changed files with patches via `/session/{id}/diff`.
- **Veronica: variant picker** in the model menu (reasoning modes like low/high per model, persisted per model, sent as `Model.Ref.variant`), **multiselect form answers** (multi-pick + free text, submitted with "Übernehmen"), and **"Undo last change"** in the chat menu (`DELETE /session/{id}/revert`).

**Compatibility:** see the migration notes above - the version jump is required together with the new allindocker release (image tag + agent mount paths).
