# Release 1.0.7 – The Chat Runs as Veronica

Feature release after 1.0.6. Drop-in compatible, one behavioral change with a documented opt-out.

* **Chat Runs as Veronica Out of the Box**
  The chat UI used to start with opencode's built-in `build` agent - a bare coding assistant with no idea it was part of Vibe4Dock (which is why asking "who are you?" produced a generic answer). The entrypoint now generates a third agent, `veronica-chat`: the same Veronica persona, but **visible** - `veronica` and `veronica-plan` stay hidden and remain exclusive to the Veronica UI. The chat preselects `veronica-chat`, so every message sent from the chat runs as Veronica, including the exact identity answer ("Ich bin Veronica von Vibe4Dock, dem Assistenten-System von der JBS New Media GmbH in Worms.").
  *Benefit: every chat answer is on-brand without any configuration.*

* **Persona Stays Multi-File And Extendable**
  Extra rules for the chat variant live in `<opencode-config>/persona/veronica-chat/*.md` - bind-mount or edit the folder on the host and restart the container; the agent file is re-assembled from the shared `persona/veronica` rules plus the `veronica-chat` extras on every start. The generated agent files (`agent/veronica*.md`) remain generated - do not edit them directly.
  *Benefit: one persona, two frontends, no duplicated rule maintenance.*

* **Opt-Out And Per-Service Override**
  `CHAT_OPENCODE_AGENT` (or the shared `OPENCODE_AGENT`) in the instance `.env` pins any other default agent for the chat - `CHAT_OPENCODE_AGENT=build` restores the pre-1.0.7 behavior. The agent selector in the chat still lists `build`, `plan` and every visible custom agent, and a manually picked agent is remembered per browser.
  *Benefit: the new default is a default, not a lock-in.*

* **Stability**
  The persona assembler now takes visibility and persona source folders as parameters and skips empty persona folders safely - a folder without `*.md` files no longer aborts the container start.

**Note for operators:** sessions are shared between the chat and the Veronica UI (same opencode data directory), but the persona is applied per message, not per session - existing chat sessions continue seamlessly and simply answer as Veronica from the next message on. The Veronica UI is unaffected: it keeps sending its own `veronica`/`veronica-plan` agents.

**Compatibility:** drop-in for 1.0.6. One behavioral change: the chat's default agent/persona (opt-out above). No new required environment variables, no schema changes.
